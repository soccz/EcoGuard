# 재현 방법론

EcoGuard 공개본은 대회 당시의 제품 화면을 복제하는 대신, 팀이 가장 중요하게 본 기술적 질문을 작은 합성 사례로 검증합니다.

> 비정형 입력에서 얻은 숫자를 어떻게 규제 검토가 가능한 추적 가능한 증거로 바꿀 것인가?

## 1. OCR 이후를 문제로 정의한 이유

OCR은 문자를 읽어도 그 값이 어떤 의미인지, 서로 다른 문서의 값이 같은 개념인지, 어느 값을 계산에 써야 하는지는 정하지 못합니다. 현업 인터뷰에서 들은 원자료는 정돈된 양식보다 자유롭게 적은 메모, 단위가 다른 표, 약칭, 빈칸, 수정 전후 값에 가까웠습니다.

따라서 공개 파이프라인은 OCR 엔진을 포함하지 않고 그 출력 경계를 JSON 레코드로 정의합니다. 각 레코드는 다음을 보존합니다.

- 문서 식별자
- 페이지·표·행 등 원본 위치
- 원래 라벨과 문자열
- OCR 또는 추출 단계의 신뢰도

preprocessing.py는 라벨 별칭을 정규 필드로 매핑하고 kg와 MT 같은 단위를 통일합니다. 가장 높은 신뢰도의 후보를 계산값으로 선택하지만, 다른 값은 삭제하지 않습니다. 정규화 후 값이 다르면 cross_document_conflict, 필수 값이 비면 missing_required_evidence를 남깁니다.

이 선택 규칙은 운영 정책이 아니라 재현 가능한 베이스라인입니다. 실제 적용에서는 문서 우선순위, 작성 시각, 서명 여부, 검증기관 등 추가 규칙이 필요합니다.

## 2. 조문 단위 법률 검색

기업들이 법률·공문서 코퍼스와 RAG를 연결할 때 중요한 것은 답변 문장의 자연스러움만이 아니라, 관련 조항을 실제로 찾았는지 검증하는 일이라는 피드백을 받았습니다. EcoGuard는 이 관점을 다음처럼 좁혀 재현합니다.

1. CBAM Regulation (EU) 2023/956의 Article 6–9
2. EUDR Regulation (EU) 2023/1115의 Article 4, 9–11
3. 조문 식별자, 제목, 한국어 검색 요약, 키워드, EUR-Lex 원문 URL
4. 질문마다 기대 조문을 지정한 5개 평가 사례
5. 기대 citation이 상위 k개 결과에 있는지 hit@k와 MRR로 측정

현재 코드는 CBAM·EUDR의 강한 도메인 단서 하나 또는 서로 다른 약한 단서 둘 이상이 있는 질문에만 문자 n-gram과 키워드 가중치를 적용하는 투명한 lexical retriever입니다. 약한 단서만 있는 경우에는 후보 조문의 키워드도 둘 이상 일치해야 합니다. 도메인 단서가 부족하거나 최소 점수에 못 미치면 결과를 만들지 않고 abstain합니다. 이는 RAG의 retrieval 평가 경계를 보여주기 위한 것으로, LLM 생성 답변이나 법률 정확도를 주장하지 않습니다. 코퍼스와 질문이 작기 때문에 결과 100%는 이 5개 고정 사례의 회수율일 뿐 일반화 성능이 아닙니다.

## 3. CBAM 노출도 시나리오

정규화한 필드를 다음 산식에 전달합니다.

    실측 내재배출량 = Σ(품목 중량(t) × 품목별 단위 내재배출(tCO2e/t))

    비용 노출도 =
      내재배출량
      × 적용계수
      × max(인증서 가격 − 원산지 탄소가격, 0)

합성 사례는 다음 두 상황을 비교합니다.

| 항목 | 실측 데이터 시나리오 | 기본값 시나리오 |
|---|---:|---:|
| 품목별 검산 | M5 502.56 + M12 608.80 | 전체 출하량에 기본값 적용 |
| 출하량 | 190 t | 190 t |
| 배출집약도 | 5.849263 tCO2e/t | 7.311579 tCO2e/t |
| 내재배출량 | 1,111.36 tCO2e | 1,389.20 tCO2e |
| 가격 가정 | €87.50/tCO2e | €87.50/tCO2e |
| 비용 노출도 | €97,244.00 | €121,555.00 |

차이 €24,311.00은 “정확한 데이터를 증명했을 때의 공식 절감액”이 아닙니다. 같은 가격 가정에서 실제 데이터와 보수적 기본값을 비교한 교육용 노출도 차이입니다. 가격·집약도·적용계수는 규제 상수로 코드에 숨기지 않고 입력과 결과에 다시 기록합니다.

## 4. 산림 변화 공개 베이스라인

대회 시연 화면에는 위성 판독과 XAI 개념이 있었지만, 기존 저장소에는 학습 코드·평가 데이터·모델 가중치가 남아 있지 않아 당시의 정확도 수치를 재현할 수 없습니다. 공개본은 그 빈칸을 감추지 않고 6×6 합성 red/NIR 픽셀로 작은 결정론적 베이스라인을 새로 제공합니다.

    NDVI = (NIR − Red) / (NIR + Red)

이전 NDVI가 산림 임계값 이상이고 감소폭이 지정 임계값 이상인 픽셀만 손실 후보로 표시합니다. 4방향 연결요소로 연속된 후보 영역과 합성 픽셀 면적도 계산합니다. 임계값, 모든 픽셀별 산식 결과, 영역 좌표와 SVG 시각화가 함께 생성됩니다. 이 fixture는 CBAM 거래 사례와 결합된 증빙이 아니라 독립된 기술 기준선입니다. 변화 탐지 코드의 재현 예시이지 EUDR 적합성 판정이나 대회 당시 모델의 복원이 아닙니다.

## 5. 하나의 증거 보고서

python -m ecoguard reproduce 명령은 정규화 이슈에 연결된 조문 citation, 고정 검색 평가, CBAM 계산과 독립 산림 기준선을 별도 JSON으로 저장한 뒤 사람이 검토하는 HTML/JSON 패킷으로 합칩니다. 각 산출물에는 schema·pipeline 버전과 입력 SHA-256이 남습니다.

중간 산출물을 남기는 이유는 결과 숫자만 맞는지 보는 테스트를 넘어 다음 질문에 답하기 위해서입니다.

- 어떤 원문이 계산에 선택됐는가?
- 다른 문서와 충돌한 값은 무엇인가?
- 어떤 조문을 근거로 보완을 요청하는가?
- 가격과 임계값은 어디에서 들어왔는가?
- 자동화가 멈추고 사람이 판단해야 하는 지점은 어디인가?
